Everything the SDKs do is plain HTTPS + JSON, so any language works. The full machine-readable description is served at **`GET /openapi.json`** (OpenAPI 3.1, no auth) — generate a typed client for Go, Java, Python, Ruby, PHP, C#, Swift and more:

```bash
npx @openapitools/openapi-generator-cli generate \
  -i http://localhost:8787/openapi.json -g go -o ./smaran-go
```

## Authentication

Send `Authorization: Bearer <api key>` on every `/v1` request. The local sandbox accepts `sk_local_dev`; a Postgres deployment issues per-tenant keys with `bun run keys` (see [Self-host](/docs/self-host)). Every query is scoped to the key's tenant.

## POST /v1/memories

Save a memory. The text is self-corrected and normalized; pure confirmation questions are skipped. A message up to 500 characters is stored as one memory; longer text is chunked at sentence boundaries.

```json
{ "userId": "u_alice", "sessionId": "call_123", "text": "my room number is 13... sorry 913", "source": "voice", "metadata": { "channel": "phone" } }
```

```json
{
  "memories": [
    {
      "id": "mem_…",
      "userId": "u_alice",
      "sessionId": "call_123",
      "text": "my room number is 913",
      "kind": "fact",
      "source": "voice",
      "metadata": { "channel": "phone", "originalText": "my room number is 13... sorry 913", "corrections": [ … ] },
      "validFrom": "…", "validUntil": null, "supersedesId": null,
      "confidenceAlpha": 1, "confidenceBeta": 1,
      "createdAt": "…", "updatedAt": "…"
    }
  ]
}
```

Skipped questions return `{ "memories": [], "skipped": "question-or-tooshort" }`. Restating a known fact returns the existing memory with `confidenceAlpha` raised instead of a duplicate; a changed number/email/phone in the same sentence frame returns a new memory whose `supersedesId` points at the one it replaced.

## POST /v1/recall

```json
{ "userId": "u_alice", "query": "where does the caller live", "topK": 5 }
```

| Field | Default | Notes |
|---|---|---|
| `query` | — | Required, up to 4,000 characters. |
| `userId` | — | Scope to one user (recommended). Omitted = whole tenant. |
| `sessionId` | — | Marks hits from this session as `tier: "session"`. |
| `topK` | `8` | 1–50. |
| `includeCrossSession` | `true` | `false` restricts to `sessionId`. |
| `rerank` | `true` | Re-order the top candidates with the reranker (built-in local cross-encoder for English, or the tenant's configured one). `false` = fastest path. |
| `rerankPool` | `40` | How many candidates the reranker sees (1–100). More = better recall, slower: on LoCoMo 20 → 75% hit@10 at ~94 ms, 60 → 80% at ~191 ms. |
| `asOf` | now | ISO timestamp: what was true at that moment. |

```json
{
  "hits": [
    { "memory": { "id": "mem_…", "text": "my room number is 913", … }, "score": 0.0164, "tier": "cross", "channels": { "dense": 1, "keyword": 1 } }
  ],
  "latencyMs": { "total": 98, "embed": 6, "search": 12, "rerank": 80 },
  "reranker": "Xenova/ms-marco-MiniLM-L-6-v2"
}
```

`score` orders results; it isn't a probability, so don't threshold on it. `channels` shows each retrieval channel's rank for debugging.

## DELETE /v1/memories/:id

Forget one memory. Returns `204`.

## POST /v1/ingest/partial · POST /v1/ingest/commit

Streaming voice turns — see [Voice concepts](/docs/voice).

```json
{ "sessionId": "call_123", "text": "my room number is" }
```

```json
{ "sessionId": "call_123", "userId": "u_alice" }
```

Commit returns `{ "saved": true, "text": "…", "memories": [ … ] }` or `{ "saved": false, "reason": "empty" | "not-substantive" | "question-or-tooshort" }`.

## GET /v1/sessions/:id/subscribe

Server-Sent Events: `memory.saved` and `memory.forgotten` for that session (your tenant only).

## Persistent mode only

With `STORE=supabase`:

- `GET /v1/profile?userId=` — consolidated profile (`404` until one exists); `POST /v1/profile/consolidate?userId=` recomputes it from recurring facts.
- `POST /v1/dpdp/right-to-forget`, `GET /v1/dpdp/export?userId=`, `POST /v1/dpdp/consent` — see [DPDP & data handling](/docs/dpdp).
- `POST /v1/graph/entities`, `/entities/extract`, `/relations`, `/traverse` — entity graph.
- `GET|POST /v1/models`, `POST /v1/models/:id/activate` — per-tenant reranker registry.

## Accounts and keys (persistent mode)

- `POST /v1/signup` — **public**. `{ "name": "Acme", "email": "ops@acme.dev", "invite": "inv_…" }` → `201` with `tenantId`, `keyId`, `apiKey` (shown once) and the plan's `limits`. Only when the server runs with `SIGNUP_MODE=open` or `invite` (`invite` requires a single-use code); rate limited per IP.
- `GET /v1/usage` — plan, stored-memory count and limits.
- `GET /v1/keys` — this account's keys (ids, labels, dates — never the raw key); the one you're calling with is marked `current`.
- `POST /v1/keys` `{ "label": "backend" }` — new key, returned once.
- `DELETE /v1/keys/:id` — revoke; takes effect immediately on the instance that handled it and within 30 s elsewhere. Revoking your last active key is refused (`409`).

Saving beyond the plan's memory quota returns `402` with code `quota_exceeded`.

## Errors

Every error has one shape, with a request id you can quote in bug reports (also in the `X-Request-Id` header):

```json
{ "error": { "code": "invalid_request", "message": "query: String must contain at least 1 character(s)", "requestId": "…" } }
```

| Status | `code` | When |
|---|---|---|
| 400 | `invalid_request` | Body/query failed validation; the message names the fields. |
| 401 | `unauthorized` | Missing, invalid or revoked API key. |
| 402 | `quota_exceeded` | The plan's memory quota is reached. |
| 403 | `forbidden` | Signup disabled, or invite missing/invalid. |
| 404 | `not_found` | Unknown route or resource. |
| 409 | `conflict` | E.g. revoking your last active key. |
| 413 | `payload_too_large` | Body over `MAX_BODY_BYTES` (default 256 KiB). |
| 429 | `rate_limited` | Over your plan's requests per minute (server default `RATE_LIMIT_PER_MINUTE`, 600); see `Retry-After`. |
| 500 | `internal_error` | Unexpected failure. Details are logged server-side without personal data. |

## Health

- `GET /health` — the process is up.
- `GET /ready` — dependencies (the database) answer; `503` otherwise. Point load balancers here.
