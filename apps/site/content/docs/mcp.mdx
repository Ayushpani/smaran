Smaran ships a Model Context Protocol server that exposes memory tools to any MCP client. It's a thin layer over your Smaran API — it stores nothing itself.

## Tools

- **`memory`** — `{ content, action: "save" | "forget", userId?, sessionId? }`. Save a fact, or forget one by describing it in plain words: the closest stored memory is deleted only if it clearly matches.
- **`recall`** — `{ query, userId?, sessionId?, limit? }`. Returns the most relevant memories.

Without a `userId`, memories go to a single shared space named `default`.

## Option A — local (stdio)

Runs on your machine, no deployment. With a Smaran API running (for example `bun run try`):

```bash
SMARAN_URL=http://localhost:8787 SMARAN_API_KEY=sk_local_dev \
  bun run apps/mcp/local-stdio.ts
```

Claude Desktop — edit `claude_desktop_config.json` (macOS: `~/Library/Application Support/Claude/`, Windows: `%APPDATA%\Claude\`):

```json
{
  "mcpServers": {
    "smaran": {
      "command": "bun",
      "args": ["run", "/absolute/path/to/smaran/apps/mcp/local-stdio.ts"],
      "env": {
        "SMARAN_URL": "http://localhost:8787",
        "SMARAN_API_KEY": "sk_local_dev"
      }
    }
  }
}
```

Cursor (`~/.cursor/mcp.json`), Windsurf and other stdio clients take the same `command` / `args` / `env` block.

## Option B — remote (Streamable HTTP)

`apps/mcp` also deploys to Cloudflare Workers (Durable Objects; the free tier is enough to start):

```bash
cd apps/mcp
# set API_URL in wrangler.jsonc to your Smaran API's public URL
bunx wrangler deploy
```

Clients connect to `https://<your-worker>/mcp` with the header `Authorization: Bearer <smaran api key>`. The key is forwarded to your API, which validates it.

<Callout tone="info" title="Telemetry">
The remote server sends tool-usage events to PostHog only when a `POSTHOG_API_KEY` binding is configured. Events carry the `userId` passed to the tool, the MCP client's name, and sizes and latencies — never memory content or queries. Leave the binding unset to send nothing.
</Callout>
