This page describes what the self-hosted Smaran API does with personal data and the endpoints that support India's Digital Personal Data Protection Act, 2023 (and GDPR). It is a technical description, not legal advice.

## Roles

When you run Smaran for your product, you are the **Data Fiduciary** (controller): you decide what is collected and why, and you own the notice and consent flow with your end users. Smaran stores, retrieves and deletes data on your instructions.

## What is stored

Each memory carries `tenantId` (your organization), optional `userId` (a stable end-user id) and optional `sessionId` (one conversation), plus the cleaned text, its embedding vector, and metadata including the original text and any corrections. Every database query filters by the API key's tenant; this is covered by automated tests, including Postgres integration tests.

Self-hosted data lives only in your own Postgres. The default embedding model runs inside the API process, so memory text is not sent to any third party unless you configure `EMBEDDER=openai` or an HTTP reranker.

## Right to erasure

```bash
curl -X POST "$SMARAN_URL/v1/dpdp/right-to-forget" \
  -H "Authorization: Bearer $SMARAN_API_KEY" -H "Content-Type: application/json" \
  -d '{"userId":"u_alice"}'
```

In one transaction this hard-deletes the user's memories, sessions and consolidated profile, and returns the counts. Consent records are retained (reported as `consentRecordsRetained`) because they are your evidence that processing was lawful. To delete a single memory, use `DELETE /v1/memories/:id`.

## Right to access / portability

```bash
curl "$SMARAN_URL/v1/dpdp/export?userId=u_alice" -H "Authorization: Bearer $SMARAN_API_KEY"
```

Returns every memory (without embeddings), session, the profile and consent records for the user as JSON.

## Consent

```bash
curl -X POST "$SMARAN_URL/v1/dpdp/consent" \
  -H "Authorization: Bearer $SMARAN_API_KEY" -H "Content-Type: application/json" \
  -d '{"userId":"u_alice","kind":"record","granted":true,"scope":"voice calls"}'
```

Each call appends a timestamped record (`kind`: `record`, `process`, `retain` or `share`) to an append-only consent log. A withdrawal is another record with `granted: false`; the most recent record per kind is the current state. Smaran records consent — your application must decide what to do when it is withdrawn (for example, call right-to-forget).

## Right to correction

A user can correct a fact by stating it again: a changed number, email or phone in the same sentence frame supersedes the old memory, and other updates are stored alongside it with the old one's confidence lowered. To remove a wrong fact outright, delete that memory.

## Retention

Memories are kept until you delete them. Delete per memory, or per user with right-to-forget, when the purpose ends.

## Logs

The API logs one JSON line per request (request id, path, status, latency, tenant id). It does not log request bodies, memory text, embeddings or SQL parameters, including when requests fail.

<Callout tone="warn" title="No automatic PII redaction">
Smaran stores the text you send. If identifiers such as Aadhaar or card numbers must not be stored, redact them before calling `save`.
</Callout>
