Voice memory differs from text memory in one important way: callers correct themselves mid-sentence. Real turns carry false starts, retractions and hesitations that don't belong in the stored record. Smaran's write path is built around that.

## The two-phase turn

Voice agents receive a stream of partial transcripts while the speaker talks, then a final transcript when the turn ends. Smaran exposes both:

- `POST /v1/ingest/partial` — adds to the session's turn buffer. Streaming ASR sends growing prefixes, so a new partial that extends the buffer replaces it, and overlap is never doubled.
- `POST /v1/ingest/commit` — takes the buffer (or a `text` you pass), cleans it, self-corrects it, and saves it once.

Nothing is stored until commit, so retractions inside a turn never reach storage. Buffers are per (tenant, session) and live in the API process.

## Self-correction

Runs on every save and commit.

### Retraction cues

Phrases that signal the speaker is taking something back: `actually`, `sorry`, `wait`, `I mean`, `scratch that`, `my mistake`, `no wait`, and a standalone `no` followed by punctuation. Romanized-Hindi cues — `nahi`, `matlab`, `galti se` — count only when they open a clause after punctuation, so ordinary sentences like "mujhe nahi pata" are untouched.

### Slot patches

When the correction is just a value — digits, an email, a phone number, or spoken numbers in English or Hindi — only that value is replaced and the rest of the clause is kept:

```
"my room number is 13... sorry 913"              → "my room number is 913"
"confirm my order — one two three four, actually four three two one"
                                                 → "confirm my order — four three two one"
"mera pin hai ek do teen, nahi teen do ek"       → "mera pin hai teen do ek"
```

### Replacements and additions

A cue in the middle of a sentence replaces the clause before it ("my name is Ayush, sorry Ayushpani" → "Ayushpani"). A cue that opens a new sentence followed by a full clause is treated as new information ("I love sushi. Sorry, I have a meeting at 5pm" keeps both). A clause introduced by ". and" is always an addition.

What was dropped is recorded on the stored memory in `metadata.corrections` (`kind`: `patch` | `replace`, `retracted`, `kept`), alongside `metadata.originalText`.

## Questions and fillers

- Each turn is split into sentences, and sentences that only ask are dropped: "is that 13 or 913?", "when is my appointment?", "mera order kya hai?". The rest of the turn is kept, so "Hi, I'm Rohan. What time do you open?" stores "Hi, I'm Rohan." Requests ("can I see Dr. Mehta on Friday?") and statements with a tag ("my address is 12 MG Road, right?") carry facts and are stored. Dropped questions are listed in `metadata.questionsDropped`.
- On the voice path, hesitation sounds (`um`, `uh`, `er`, `hmm`) and stutters ("my my") are removed. Words that carry meaning — `like`, `actually` — are kept.
- Hinglish filler words (`matlab`, `achha`, `yaani`…) are removed when surrounded by content.

## Languages

English, Hindi (Devanagari) and romanized Hinglish go through the same endpoints. Text is never translated — code-switched content is stored as spoken, and the default multilingual embedding model places "mera ghar Andheri mein hai" next to "I live in Andheri". The detected language and a code-switch flag are stored in metadata.

## Across turns and sessions

When a user restates a fact, Smaran corroborates the existing memory instead of storing a duplicate. When a number, email or phone in the same sentence frame changes ("my room number is 13" → "…913"), the old memory is closed and the new one supersedes it; it stays visible to point-in-time recall (`asOf`). Other changes ("I am allergic to peanuts" → "…penicillin") keep both — Smaran never hides a fact it can't be sure was replaced.

## What the pipeline does not do

- **No LLM in the write or recall path.** Cleaning and correction are deterministic; recall uses a small local embedding model plus keyword search, then a small local cross-encoder re-orders the top candidates. Recall is ~140 ms in-process on CPU (`rerankPool: 20` brings it to ~95 ms), or ~15 ms with `rerank: false` (see RESULTS.md).
- **No PII redaction on save.** Redact at your edge before calling `save` if you don't want certain identifiers stored.
